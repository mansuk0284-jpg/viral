# Compete Insight — 경쟁력 × 바이럴

원본: `data/백화점 리스트.xlsx` (영업팀 제공).
**경쟁력 = 당사 매출 ÷ X사(LG) 매출 배수.** 1.0 이면 대등.

## 자료를 다룰 때 반드시 지킬 것

| 규칙 | 이유 |
|---|---|
| **금액을 내보내지 않는다** | 사내 실적이다. `build_compete.py` 가 배수만 산출한다 |
| **`매장명 + MX` 는 제외** | 모바일 매장이다. LG에 모바일 매장이 없어 비교가 성립 안 한다(사용자 확인) |
| **양사 모두 입점한 매장만** | 한쪽이 0이면 미입점이라 배수가 0/무한이 된다 |
| **화면에 상시 노출 금지** | hover 로만 보여준다. 상시 노출하면 대시보드가 실적표가 되고 옆자리에 그대로 보인다 |

## 실행

```
python scripts/build_compete.py         # xlsx → artifacts/compete.json + web/assets/compete-data.js
python scripts/compete_viral_link.py    # 상관·사분면 → 리포트 + web/assets/compete-link.js
```

## 매장명 잇기 — 별칭이 필수다

경쟁력 자료와 대시보드 표기가 다르다. 공백만 지우면 **70곳 중 51곳**밖에 안 붙는다(실측).
`build_compete.ALIAS` 에 15개를 넣어 **66곳**까지 올렸다.

```
현대무역 → 현대무역센터 / 현대본점 → 현대압구정 / 갤러리아본점 → 갤러리아압구정
신세계타임스퀘어 → 신세계영등포 / 롯데스타시티 → 롯데건대 / 현대킨텍스 → 현대일산
롯데중동 → 롯데부천 / 롯데부산 → 롯데부산본점 …
```

남은 4곳(신세계 죽전·신세계 아산·갤러리아 아산·롯데 광주)은 **경쟁력 자료에 없다.**
툴팁에 "경쟁력 자료에 없는 매장입니다"로 정직하게 표시한다.

## 핵심 발견 — 바이럴과 경쟁력은 거의 무관하다 ★

62개 매장 실측(2026-08-21):

| 대조 | r |
|---|---|
| 바이럴 건수 ↔ 경쟁력 | **+0.14** |
| 삼성 점유율 ↔ 경쟁력 | **+0.19** |

**"바이럴이 잘 되면 경쟁력도 높다"는 성립하지 않는다.** 이걸 "관계 있다"고 포장하면 거짓이다.

대신 **두 축을 교차해 사분면으로 나누면 어긋난 칸이 곧 할 일**이 된다:

| 사분면 | 곳 | 뜻 |
|---|---|---|
| 둘 다 강함 | 18 | 이 방식을 확산 |
| **말은 도는데 안 팔림** | **13** | 상담·재고·가격 점검 |
| **잘 파는데 안 알려짐** | **13** | 후기 유도가 비어 있음 |
| 둘 다 약함 | 18 | 기본기부터 |

기준선은 **중앙값**을 쓴다(평균은 소수 매장에 끌려간다).
후기 10건 미만 매장은 비율이 요동쳐 대조에서 뺀다.

## 화면 규칙

- `web/compete-hint.js` — 문서 전체 위임. **매장 이름 요소에 `data-store="<매장명>"` 만 달면** 된다.
  화면마다 코드를 넣지 않는다(재렌더에도 계속 동작).
- 툴팁은 **배수 + 등급 + 3년 추이 + 기간**만. 금액 없음.
- 매장 대시보드에는 `.cx-comp` 블록으로 **사분면 진단과 할 일**을 함께 띄운다
  — 배수만 크게 띄우면 상관이 없다는 사실이 가려진다.
