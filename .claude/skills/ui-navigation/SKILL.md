# UI Navigation — 화면 이동·기간 선택 공용 규칙

새 분석 페이지를 추가할 때 **이동과 기간은 새로 만들지 않는다.** 공용 모듈을 쓴다.

## 왜 이 규칙이 생겼나 (2026-08-14 실측)

화면마다 따로 만들었더니 이동 수단이 5종류가 됐고 실제로 문제가 났다.

| 증상 | 실측 |
|---|---|
| 플로팅 '← 처음으로'와 헤더 버튼이 **겹침** | 제휴카페 화면에서 겹침 확인 |
| 라벨이 동작과 **불일치** | '‹ 카페 목록'인데 실제로는 처음 화면으로 감 |
| 같은 화살표가 **다른 뜻** | 페이저 `‹ ›`(단계) vs 월 스테퍼 `‹ ›`(달) |
| 기간 버튼이 **안 보임** | 아이콘에 마우스를 올려야 펼쳐짐(접힘폭 0 · 실제폭 977) |
| `showIntro`가 클래스를 **일부만** 정리 | `view-cx`/`view-af`가 남아 화면이 꼬임 |

## 이동 — `web/nav.js` (window.VNAV)

```js
// 화면 진입 시
VNAV.push({ id: "store:롯데 부산본점", label: "롯데 부산본점",
            open: () => openStoreScope("롯데 부산본점") });
// 헤더 맨 왼쪽에
`${window.VNAV ? VNAV.bar() : ""}`
// 화면을 다시 그린 뒤
VNAV.sync();
```

- `bar()` = `⌂ 처음` `‹` `›` 세 버튼. **어느 화면이든 같은 자리(헤더 맨 왼쪽)·같은 모양.**
- 클릭 처리는 `nav.js`가 문서 한 곳에서 받는다. **화면마다 리스너를 붙이지 말 것**
  (붙이면 재렌더 때마다 중복 등록돼 한 번 클릭에 여러 번 실행된다).
- `Alt+←` / `Alt+→` 도 같은 동작.
- `open`은 그 화면을 **다시 그리는 함수**다. 이게 있어야 뒤로/앞으로가 실제로 복원된다.
- 결과 화면에서 플로팅 `.back-float`는 **띄우지 않는다**(`nav.css`가 숨김). 헤더 내비가 대신한다.

## 기간 선택

- **항상 보이게 둔다.** hover 로 펼치는 방식 금지 — 버튼이 어디 있는지 알 수 없다.
- 화살표 기호가 이동과 겹치지 않게 한다. 월 이동은 `af-nav`처럼 **기간 바 안에** 두어
  문맥으로 구분되게 하고, 페이지 이동 화살표(`VNAV`)와 나란히 두지 않는다.
- 첫 진입은 **현재 월**. 그 달에 표본이 없으면 표본 있는 가장 최근 달로 내린다.
- 폭이 모자라면 **줄바꿈**시킨다(잘라내지 않는다). 잘린 버튼은 없는 버튼과 같다.

## 새 페이지 만들 때 체크리스트

1. 헤더 맨 왼쪽에 `VNAV.bar()`
2. 진입 함수에서 `VNAV.push({id, label, open})`
3. 재렌더 후 `VNAV.sync()`
4. 자체 뒤로가기 버튼을 **만들지 않는다**
5. 기간이 필요하면 상시 노출 + 현재 월 기본
6. 검증: 다른 화면에서 들어왔다 나갔다 하며 **뒤로/앞으로가 실제로 복원되는지**,
   버튼이 **겹치지 않는지**(getBoundingClientRect 교차 검사), 스크롤 0 인지

## 전체 점검에서 잡은 것 (2026-08-21)

### 1. view-* 클래스가 겹겹이 쌓였다 ★
화면마다 `classList.add("mode-results","view-…")` 만 하고 지우지 않아,
다이렉트웨딩 → 제휴카페 → 매장 → 리뷰로 옮기면 클래스가 이렇게 됐다:

```
mode-results view-channel view-cafe view-af view-cx view-nr
```

CSS 가 서로 간섭하고, `showIntro` 는 3개만 지워서 **'처음으로' 후에도 view-nr 이 남았다.**

→ **`window.setView("view-channel","view-cx")`** 한 곳으로 통일했다.
켤 것만 남기고 나머지는 끈다. `nav.js` 의 home 도 목록을 따로 들지 않고 `showIntro` 에 위임한다.
**새 화면을 추가하면 `app.js` 의 `VIEWS` 배열에만 넣는다** — 목록이 두 곳이면 반드시 어긋난다.

### 2. 진입 경로 없는 층은 지운다 — 부울경 사례
전국 대상이 되면서 `bu`(부울경) 층은 **지도에서 도달할 수 없는데 브레드크럼에만 남았다.**
눌러 들어가면 표본 42건짜리 요약만 있고 더 내려갈 수도 없는 막다른 길이었다.
"왜 부울경만 있고 수도권은 없나"에도 답할 수 없다.
→ `LV` 를 `["nation","region","store"]` 3단으로 줄이고 관련 분기를 전부 걷어냈다.

**규칙: 드릴 단계는 지도·목록에서 실제로 갈 수 있는 것만 둔다.**

### 3. 메인에서는 내비를 감춘다
결과 화면이 아닐 때 `⌂ ‹ ›` 가 보이면 눌러도 아무 일이 없어 고장처럼 보인다.
`body:not(.mode-results) .vnav { display:none }`.

### 4. 0건 타일은 자리만 차지한다
채널 타일 11개 중 8개가 사실상 0건이었다(결다모·웨딩북·맘스홀릭·당근 등은 수집 시도조차 안 함).
수집 계획이 없는 5개를 걷어내고, 정작 실데이터 8,348건인 **네이버 리뷰 타일을 추가**했다.
**타일은 "수집했거나 수집할 채널"만 둔다.**

## 화면은 3층이다 — 이걸 몰라서 이동이 계속 어긋났다 (2026-08-21 2차)

```
1번 메인      (클래스 없음)          애플카드 2장 + 포털
   ↓ 포털 클릭 = revealPortal()
2번 채널타일  portal-open            좌=혼수채널 / 우=제휴카페
   ↓ 타일 클릭
3번 결과화면  portal-open + mode-results + view-*
```

**`mode-results` 를 벗는다고 1번이 되지 않는다.** `portal-open` 이 남으면 2번이다.
이 구분이 없어서:

- `showIntro()` 가 `portal-open` 을 안 지워 **'처음'이 늘 2번에 멈췄고, 1번으로 갈 길이 아예 없었다.**
- 2번에는 내비를 아예 안 그렸다(`body:not(.mode-results) .vnav{display:none}` 에 걸림).
- 스택의 portal 엔트리 `open` 이 `revealPortal` 이었는데, 이미 열려 있으면 가드에 걸려 **아무것도 안 하고 반환** → 뒤로가 먹통.

**규칙 — 목적지마다 함수를 따로 둔다.**

| 가고 싶은 곳 | 함수 | 하는 일 |
|---|---|---|
| 1번 메인 | `showIntro()` | view-* + mode-results 제거 **+ `closePortal()`** |
| 2번 채널타일 | `openPortal()` | `exitResults()` 로 결과만 벗고, 안 열려 있으면 `revealPortal()` |
| 3번 결과 | `setView(...)` | 켤 view 만 남긴다 |

`closePortal()` 은 `revealPortal()` 이 한 일을 정확히 되짚는다 —
타일을 원래 부모로 되돌리고(원위치를 초기화 때 기억해 둔다), 무대·그룹·제휴모자이크를 감추고,
`portal-open` 을 벗고, 포털을 다시 보이게 하고, `applyClosed()` 로 타일을 블랙홀에 넣는다.

## 하단 페이저(⤒ ‹ ›)는 없앴다 — 내비가 두 벌이면 반드시 어긋난다

같은 화면 상단에 VNAV 가 있는데 하단에 페이저가 또 있었다. 그런데 **둘은 서로 다른 것을 셌다**:

- 상단 `‹` = **지나온 화면**(스택)
- 하단 `‹` = **드릴 단계**(전사↔지역↔매장)

생김새가 같은 두 버튼이 화면마다 다른 곳으로 갔다. 하단을 걷어내고 이동은 VNAV 하나로만 한다.
드릴은 지도·표를 직접 누르는 것으로 충분하다.

## 새 화면을 만들 때 반드시 확인 — 내비를 그렸는가

`VNAV.push()` 만 하고 **`VNAV.bar()` 를 안 그리면 들어가서 나올 수 없는 막다른 화면**이 된다.
채널 단일 화면(블로그·유튜브 등)이 실제로 그랬다 — 스택엔 있는데 버튼이 없었다.

**두 가지가 짝이다: `push()` + `bar()`.** 하나만 하면 반쪽이다.

## 글자가 갈라지지 않게 — `web/text-fit.css` (2026-08-21)

실측된 증상: `100%` 가 "100" / "%" 두 줄, `롯데 부산본점` 이 두 줄, 라벨 `지역평균 대비` 가 두 줄.

**원인은 하나다 — 전체화면 모드가 글자를 일괄로 키우는데 칸 폭은 고정이다.**
`.rv-sh` 는 12px→18px 가 되는데 칸은 42px 그대로, 95px KPI 칸의 설명 라벨도 10.5px→18px 로 부풀었다.
칸에서 커야 할 것은 **수치**이지 라벨이 아니다.

`web/text-fit.css` 가 화면 공통으로 못 박는 것:

| # | 규칙 |
|---|---|
| 1 | 수치와 단위는 `nowrap` — `100`과 `%`는 절대 안 갈라진다 |
| 2 | 매장·지점 이름은 한 줄, 넘치면 말줄임(줄을 늘리지 않는다) |
| 3 | 버튼 글자는 세로로 서지 않는다 |
| 4 | `word-break: keep-all` — 없으면 "정수기·청 / 소기" 처럼 아무 데서나 잘린다 |
| 5 | 좁은 수치 칸은 **칸을 넓힌다**. 글자 축소는 마지막 수단 |
| 6 | 좁은 칸의 보조 라벨은 확대 상한(12px) |
| 7 | 문장 속 강조 조각은 통째로 넘긴다(keep-all 은 가운뎃점을 못 막는다) |
| 8 | 데이터 타일이 아닌 이동용 헤드 타일은 크기를 따로 준다 |

**이 파일은 화면별 CSS 뒤에 링크해야 이긴다.**

### 검사 방법 — 눈으로 찾지 말고 재게 한다

패딩 때문에 `height > lineHeight` 는 오탐이 난다(버튼 "적용"이 걸렸다).
**Range 로 텍스트가 실제 걸친 줄 수를 센다:**

```js
const rg = document.createRange(); rg.selectNodeContents(el);
const tops = new Set([...rg.getClientRects()].filter(r => r.height > 1).map(r => Math.round(r.top)));
if (tops.size > 1) /* 갈라졌다 */;
```

인라인 강조는 `el.getClientRects()` 의 top 종류로 센다. 새 화면을 만들면 이걸 전 화면에 돌린다.

## 기간 줄 — 연도는 접고 그 해 월만 편다 (2026-08-21)

`전체 + 연도6 + 월12 = 19개` 버튼이 한 줄에 늘어서 서로 겹치고 누르기 어려웠다.

```
[2026 ▾]  1월 2월 3월 4월 5월 6월        ← 한 줄, 7개
   └ 올리면: 2026년 / 2025년 / … / 전체 기간
```

- `st.navY` = **줄에 펼쳐 놓을 연도**(선택된 기간과 별개다). 기본은 데이터의 마지막 해.
- 연도 창은 `hover` 와 `focus-within` 둘 다로 연다 — 키보드로도 닿아야 한다.
- **기간을 고르면 줄도 그 해로 따라 옮긴다.** 안 그러면 고른 달이 줄에 없어 어디 있는지 모른다.
- `perLab()` 은 키에서 직접 라벨을 만든다. `PERIODS` 에는 올해 월만 있어서
  다른 해의 월을 고르면 **"2025-03" 같은 날것이 그대로 화면에 나왔다.**

## 이름을 줄이지 않고 전부 보여준다 — `web/text-fit.js`

말줄임(`…`)을 걷어냈다. 사용자 지적: **"신세계센텀…과 같이 줄여표시하는 경우에는
실제 어디인지 알 수 없는 경우도 있어."** 맞는 말이다 — 신세계 센텀시티인지 롯데 센텀인지
구분이 안 된다.

**폭은 고정하고 글자만 줄인다.** 폭을 늘리면 옆 칸이 밀려 레이아웃이 무너진다.

```js
el.style.fontSize = "";                       // 기준 크기부터 다시 잰다
while (el.scrollWidth > el.clientWidth + 0.5 && fs > 9.5) { fs -= 0.5; … }
```

- 하한 **9.5px** — 이보다 작으면 못 읽는다.
- 줄어든 요소에는 `title` 을 달아 마우스로도 전체 이름을 볼 수 있게 한다.
- `MutationObserver` 로 화면이 다시 그려질 때마다 자동 적용한다.
  **화면마다 직접 부르게 하면 반드시 잊는다.**
- CSS 쪽은 `white-space: nowrap; overflow: hidden` 만 남기고 `text-overflow` 는 뺀다.

## 긴 글은 문장 단위로 끊는다

진단·액션이 한 덩어리로 이어져 읽기 어려웠다("정돈된 느낌이 안 난다").
`para()` 로 `.` + 공백에서 끊어 `<span class="pl">` 블록으로 만든다.
**소수점(1.07배)은 마침표 뒤에 공백이 없어 걸리지 않는다** — 그래서 이 방식이 안전하다.


## 카드가 사라진다 — `auto` 행 + 글자 갈라짐 (2026-08-21, 매장 상세 우측)

**증상.** 다이렉트웨딩 → 지역 → 매장 화면의 `.sv-right` 743px 안에 내용이 1498px.
`grid-template-rows` 계산값이 `228.7 / 498.4 / 0px` 이 되어 3행에 놓인
"현장 액션"·"이 매장 후기" 두 카드가 **18px 로 찌부러져 화면에서 사라졌다.**

**원인은 두 겹이었다. 겉으로 보이는 쪽이 진짜 원인이 아니었다.**

1. **진짜 범인 = 글자 갈라짐.** `.it-v` 의 "100%" 가 44px 칸에 19.5px 로 들어가
   `1 / 0 / 0%` 세 줄이 됐다. 한 줄 30px → **62px**. 품목 4줄짜리 목록이 **486px**.
   즉 카드가 부푼 건 정보가 많아서가 아니라 **글자가 칸에 안 들어가서**였다.
   → 높이 문제로 보이면 **먼저 폭을 의심한다.** `scrollWidth - clientWidth` 를 재라.
2. **행 높이 `auto auto 1fr`.** 부푼 앞 두 행이 공간을 다 먹고 3행에 0px 만 남았다.
   → `minmax(0, Nfr)` 로 **비율 배분**. `auto` 는 "앞 행 우선"과 같은 말이다.

**`body.view-cafe` 가 높이 제한을 푸는 규칙에 주의.** 전체화면 모드가
`.pf-items { max-height: none }` 로 상한을 걷어내 버려, 좁은 화면용 `max-height` 가
전부 무력화돼 있었다. 전체화면 규칙은 **글자만 키우고 칸은 그대로 두는** 같은 뿌리의
사고를 계속 낸다(`web/text-fit.css` 머리말 참고).

### 배치로 푸는 법 — 큰 카드끼리 행을 나눠 쓰게 한다

우측 5카드를 2열 3행으로 놓으면 **큰 카드 셋(sc·mgr·rev)이 서로 다른 행을 하나씩**
차지해, 행 합계 최소치가 `195+318+246 = 759px` 로 고정된다. 좌열은 473px 만 쓰고
135px 를 논다. **행을 4개로 늘리고 span 을 엇갈리게** 두면 같은 내용이 634px 로 내려간다.

```
   1행 │ sc-card      │ ┐ sv-profile (1~2행)
   2행 │ mgr-card     │ ┘
   3행 │  (mgr 계속)  │ ┐ sv-rev (3~4행)
   4행 │ sv-actcard   │ ┘
```

한 카드의 여유가 옆 카드의 부족을 메운다. **글씨를 줄이기 전에 이걸 먼저 한다.**

### 재는 법 (짐작 금지)

```js
// ① 내부 스크롤이 남은 요소
[...document.querySelectorAll('.sv-right *')].filter(e=>{const s=getComputedStyle(e);
  return e.offsetParent && /auto|scroll/.test(s.overflowY+s.overflow) && e.scrollHeight-e.clientHeight>4;});
// ② 넘쳐서 잘린 요소(overflow:hidden 이라 눈엔 안 보인다) — 세로·가로 둘 다
[...document.querySelectorAll('.sv-right *')].filter(e=>e.offsetParent &&
  (e.scrollHeight-e.clientHeight>4 || e.scrollWidth-e.clientWidth>1));
// ③ 카드별 "박스 vs 필요" — 어디에 여유가 있고 어디가 모자란지 한눈에
```
③ 이 핵심이다. 카드마다 `box`(실제 높이)와 `need`(자식 scrollHeight 합 + gap + padding)를
같이 찍으면 **fr 값을 눈대중이 아니라 산수로 정한다.** 실측 결과(1280x800):
`profile 316/332 · sc 174/178 · mgr 291/299 · act 109/122 · rev 245/275` → 전부 0 넘침.

**매장마다 내용 길이가 다르다. 한 곳만 보고 끝내면 안 된다.** 전 지역·전 매장(25곳)을
순회해 최댓값으로 맞췄다. 1440x900 과 1280x800 둘 다 확인한다 — 낮은 화면은
`@media (min-width:1180px) and (max-height:860px)` 로 밀도를 한 단계 더 조인다.

## 카드가 화면에서 사라지는 이유 — 행 높이를 `auto` 로 두면 안 된다 (2026-08-21)

매장 상세 우측(`.sv-right`)에서 **"현장 액션" 18px, "이 매장 후기" 18px** 로 찌부러져
사실상 안 보였다. 743px 칸에 내용 1498px 을 넣은 것이 근본 원인이지만, 방아쇠는 따로 있었다.

```
grid-template-rows: auto auto minmax(0, 1fr)
계산 결과: 228.7px / 498.4px / 0px          ← 3행이 0
```

**`auto` 행은 콘텐츠가 원하는 만큼 다 가져간다.** 앞 두 행이 공간을 다 먹으면
`1fr` 인 마지막 행에는 **0px 만 남는다.** 카드가 사라져도 CSS 오류는 나지 않는다.

→ **모든 행을 `minmax(0, Nfr)` 로 비율 배분한다.** 어느 행도 0이 되지 않는다.

```css
grid-template-rows: minmax(0, 1fr) minmax(0, .82fr) minmax(0, .815fr) minmax(0, .685fr);
```

3행 → 4행으로 늘리고 큰 카드를 2행에 걸치게(`grid-row: 1 / 3`) 배치하면 균형이 잡힌다.
실측: 5개 카드가 402 / 217 / 362 / 148 / 333px 로 모두 실체를 갖고 내부 스크롤 0.

### 전체화면 모드가 높이 제한을 푸는 것을 조심하라

```css
@media (min-width: 1180px) { .sv-right > .sv-profile .pf-items { max-height: 132px; } }
body.view-cafe .sv-profile .pf-items { max-height: none; }   /* ← 이게 뒤에서 무력화 */
```

`body.view-cafe`(전체화면) 규칙이 **뒤에 있어서 이겼다.** 그래서 품목 목록이 486px 로 부풀었다.
**글자를 키우는 규칙과 칸을 푸는 규칙은 다르다.** 확대 모드에서도 칸 제약은 유지해야 한다.
(같은 뿌리로 `100%` 가 `100`/`%` 로 갈라진 적이 있다 — `web/text-fit.css` 참조)

### 찌부러진 카드를 찾는 법

높이가 40px 미만이면 사실상 안 보이는 것이다. 눈으로 찾지 말고 재라:

```js
[...document.querySelector('.sv-right').children]
  .filter(c => getComputedStyle(c).display !== 'none')
  .map(c => c.className + ':' + Math.round(c.getBoundingClientRect().height));
```

## 메인 카드 이미지 — 시안을 실제로 띄워 놓고 고른다 (2026-08-21)

"이미지가 너무 작다. 정형화된 자리 말고 자연스럽지만 세련되게" — 메인은 첫인상이라
머리로 정하지 말고 **세 안을 나란히 띄워 눈으로 비교**했다.

| 안 | 결과 |
|---|---|
| A 원을 키워 오른쪽으로 | 원 오른쪽이 카드 경계에서 딱 잘리고 왼쪽에 초승달 여백이 남았다 |
| C 원을 훨씬 키워 일부만 | 확대감은 좋으나 SAMSUNG·LG 로고가 잘려 **맥락이 사라졌다** |
| **B 칸을 가득 채우고 가장자리를 흐림** | 이미지가 가장 크고 맥락도 온전하다 ← 채택 |

**원형 마스크로 작게 가두는 것보다, 칸을 가득 채우고 가장자리를 비네팅으로 흐리는 쪽이
훨씬 크고 세련돼 보인다.** 직사각형 사진이 아니라 카드에서 피어난 빛처럼 읽힌다.

### 초점은 그림 내용으로 정한다 — 눈대중 금지

`object-fit: cover` 는 넘치는 쪽을 자른다. 그림의 주인공이 어디로 가는지 계산해야 한다.

```python
# 밝기 무게중심으로 소용돌이(주인공) 위치를 찾는다
thr = 하위 8% 밝기
중심 = 어두운 픽셀들의 평균 좌표     # → 원본 세로 58.4%
```

그대로 두면 화면 세로 **77%** 까지 내려가 카드 밑단에 붙었다.
`object-position` 세로를 56% 로 올려 로고·소용돌이·사람이 한 화면에 들어오게 맞췄다.

### 그림을 옮기면 클릭존도 같이 옮긴다

`portal-hole`(클릭존)과 `ap-cue`(안내 아이콘)를 두고 오면
**보이는 그림과 눌리는 자리가 어긋난다.** 실제로 원 바깥 빈 여백이 눌리는 클릭존이 된 적이 있다.
그림 속 소용돌이 자리(가로 54% · 세로 61%)로 함께 옮기고, 셋의 중심이 일치하는지 재서 확인한다.

```js
const R = e => { const r = e.getBoundingClientRect();
  return [Math.round(r.left + r.width/2), Math.round(r.top + r.height/2)]; };
// 이미지 · 클릭존 · 큐의 중심이 같은가
```

## 기간 줄 2차 — 월도 칩으로 접었다 (2026-08-21)

```
1차:  전체 + 연도6 + 월12 = 19개 버튼      → 겹치고 누르기 어려웠다
2차:  [2026 ▾] 1월…8월      = 9개          → 그래도 길다
3차:  [2026 ▾] [8월 ▾]      = 2개 · 182px  ← 지금
```

- 칩을 **누르면** 그 단위 전체(연도 전체 / 그 달), **올리면** 목록이 열린다.
- 월 창은 최대 13항목(연간 전체 + 12달)이라 세로로 두면 화면을 넘는다 → **3열 격자**.
  '연간 전체'만 한 줄을 다 쓴다(월과 성격이 달라 구분이 필요하다).
- **첫 화면은 현재 월**(`NOW_M`). 데이터에 이번 달이 아직 없으면 마지막 달로 물러선다.

### 칩이 둘이면 서로 어긋나지 않게 맞춰야 한다

실측으로 잡은 어색함 셋:

| 상황 | 문제 | 고침 |
|---|---|---|
| 연도만 2025로 바꿈 | 칩은 `2025` 인데 보고 있는 건 `2026년 3월` | 같은 달의 그 해(`2025-03`)로 함께 옮긴다. 그 해에 그 달이 없으면 그 해 마지막 달 |
| 전체 기간 | 두 칩이 나란히 `전체` — 같은 말을 두 번 | 월 칩은 `월 선택` 으로, 옅게 |
| 전체에서 연도 누름 | 아무 일도 안 일어남 — 고장처럼 보임 | 연도를 골랐다는 건 그 해를 보겠다는 뜻이니 그 해 연간으로 |

**규칙: 칩에 적힌 것과 실제로 집계 중인 기간이 항상 같아야 한다.**

## 내비를 어디 두느냐가 레이아웃을 망칠 수 있다 (2026-08-21)

2번 페이지(채널 타일) 내비를 **좌측 제목 블록 안에** 넣었더니 좌측만 42px 밀려
좌우 타일 무대가 어긋났다:

```
좌 채널 타일   552px      ← 내비가 밀어낸 만큼 줄었다
우 제휴카페    600px
```

정작 주인공인 타일이 좌우로 안 맞는다. 내비 하나 때문에.

→ **두 열의 공통 부모(`hero-grid`) 위에 별도 줄로 뺀다.** 좌우가 함께 내려가므로 균형이 유지된다.
   실측 결과 좌우 모두 600px, 상단·하단 차 0.

**단, 그리드 밖에 두면 정렬이 깨진다.** `hero-grid` 는 가운데 정렬 + 좌우 패딩을 갖는데
그 밖에 두면 내비가 화면 맨 왼쪽 구석(x=0)에 붙는다.
→ 같은 `width` 와 `padding` 을 줘서 **제목과 같은 세로선**에 맞춘다(실측 200px 일치).

### 정규식을 문자열로 짜지 마라

`new RegExp("^" + m + "월(\s|\(|$)")` 가 `/^8월(s|(|$)/` 로 망가져 **화면이 통째로 죽었다.**
역슬래시가 소스 → 문자열 → 정규식으로 두 번 먹힌다. 셋 다 맞추기 어렵다.
→ 이런 간단한 매칭은 **문자열 비교로 간다.**

```js
const pre = m + "월";
C.periods.find((p) => p === pre || p.indexOf(pre + " ") === 0 || p.indexOf(pre + "(") === 0);
```

## 브라우저 뒤로/앞으로를 쓴다 (2026-08-21)

사용자 지적: **"크롬의 뒤로가기 기능을 쓰면 안 돼? 왜 작동이 안 되지?"**

안 되던 이유는 단순했다 — `nav.js` 가 **자체 스택만** 굴리고 브라우저 히스토리에는
아무것도 안 쌓았다. 그래서 크롬 뒤로가기를 누르면 화면이 아니라 **사이트를 떠났다.**

```js
// 화면을 열 때 한 칸 쌓는다. 함수는 직렬화할 수 없으므로 state 엔 id 만.
history.pushState({ vid: entry.id }, "", "#" + encodeURIComponent(entry.id));
REG.set(entry.id, entry);          // 실제 항목은 맵에 둔다

window.addEventListener("popstate", (e) => { … REG.get(e.state.vid).open() … });
```

**주의 셋:**
1. **복원 중 플래그**(`restoring`) — 뒤로가기로 되돌아온 화면이 다시 `push` 하면
   히스토리가 제자리를 맴돈다. 복원 중의 push 는 쌓지 않는다.
2. **첫 진입에 기점을 놓는다** — `history.replaceState({vid:null})`.
   이게 없으면 첫 뒤로가기가 사이트를 떠난다.
3. **Alt+← 가로채기는 뺐다** — 이제 브라우저가 직접 popstate 를 주므로
   가로채면 오히려 히스토리와 화면이 어긋난다.

## 분석 화면은 같은 옷을 입는다 — `web/analysis-ui.css` (2026-08-21)

매장별과 채널별이 따로 자라서 실측이 이렇게 갈려 있었다:

| | 채널별 | 매장별 |
|---|---|---|
| 머리글 높이 | 54px | **106px** |
| 제목 | 30px | **34px** |
| 카드 패딩 | 25.9px | 22/20px |
| 카드 반경 | 22px | 20px |
| 기간칩 높이 | **48px** | 37px |

같은 성격의 화면이 다른 옷을 입으면 옮겨 다닐 때마다 다시 적응해야 한다.
**조밀한 쪽을 기준으로** 맞춘다 — 한 화면 원칙에 유리하고, 큰 글씨가 옆 항목을
밀어내는 문제도 함께 준다. 값은 `:root` 변수 네 개(`--an-radius/pad/gap/title`)에만 둔다.

### 구성까지 억지로 같게 만들지 않는다

매장별은 머리글에 제목이 있고, 채널별은 본문 좌측 칼럼에 있다(크럼이 따로 있어서).
구성을 강제로 통일하면 각 화면이 어색해진다.
→ **높이만 맞춘다**(60px). 그래야 화면을 옮겨도 본문 시작선이 흔들리지 않는다.

### clamp() 한 곳만 남으면 화면 폭에 따라 다시 갈린다

전국 칼럼 제목만 `clamp(22px, 2.2vw, 30px)` 이라 1440 에서는 30px 로 같았는데
**1280 에서 28.16px** 이 되어 매장별(30px)과 갈렸다.
→ 공용 변수로 고정. 통일했다면 **모든 뷰포트에서** 재서 확인한다.

### 캐시 번호를 올려도 index.html 자체가 캐시될 수 있다

새 CSS 를 링크했는데 브라우저가 옛 `index.html`(v209)을 쥐고 있어
**파일이 아예 로드되지 않았다.** `?nocache=` 같은 쿼리를 붙여 다시 받아야 한다.
검증할 때 `document.styleSheets` 에 새 파일이 있는지부터 확인할 것.

## 공유 컨테이너에 리스너를 달면 화면이 서로 오염된다 (2026-08-24)

기간 모듈(`VPER.bind`)이 `#channelPanel` 에 클릭 리스너를 달고 있었다.
그런데 그 컨테이너는 **모든 화면이 함께 쓴다.**

```
제이웨딩을 열면 → #channelPanel 에 리스너가 붙는다
다이렉트웨딩으로 전환 → 화면은 바뀌지만 리스너는 남는다
거기서 기간 칩을 누르면 → 제이웨딩의 onChange 가 발동
                        → 화면이 제이웨딩으로 되돌아간다  ← 실측
```

`dataset.vperBound` 로 "한 번만 붙인다"고 막아 둔 것이 오히려 화근이었다 —
한 번 붙은 리스너가 다른 화면까지 따라다닌다.

**→ 자기 UI 묶음(`.vper`)에만 단다.** 그 요소는 화면을 다시 그릴 때마다 새로 생기므로
서로 섞이지 않는다. **위임은 "내가 지우는 요소" 위에서만 한다.**

## 새로고침하면 히스토리와 화면이 어긋난다

새로고침 뒤 `history.state` 에는 이전 화면 id 가 남는데 화면은 메인부터 그려진다.

```
해시 #cafe-analysis · history.state {vid:"cafe-analysis"} · 화면은 메인
```

이 상태로 뒤로/앞으로를 누르면 엉뚱한 곳으로 간다.
화면을 여는 함수는 직렬화할 수 없어 되살릴 수도 없다.
**→ 로드할 때 기점으로 `replaceState` 하고 해시도 지운다.** 새로고침하면 메인부터 시작한다.

## 2열로 접을 때 열 수도 줄여야 한다

매장 목록을 2열로 접었더니 **이름 칸이 0px 로 사라졌다.**
폭이 반이 됐는데 여덟 칸(고정폭 합 232px)을 그대로 두면 `minmax(0, …)` 인 칸부터 0으로 눌린다.
**→ 2열에서는 꼭 필요한 칸만 남긴다**(이름·막대·비중·건수). 순위·갭은 한 열일 때만.

## 검사기는 "보이는 것"을 재야 한다

이번 점검에서 실제로 잡힌 것들 — 모두 **CSS 오류 없이** 조용히 잘못돼 있었다:

| 증상 | 재는 법 |
|---|---|
| 이름이 잘림 | `el.scrollWidth > el.clientWidth` |
| 칸이 0px 로 사라짐 | `clientWidth` 를 직접 확인 |
| 카드가 찌부러짐 | 높이 40px 미만 |
| 글자가 갈라짐 | Range 의 `getClientRects()` top 종류 수 |
| 화면 오염 | 전환 후 본문 텍스트 앞부분 비교 |
