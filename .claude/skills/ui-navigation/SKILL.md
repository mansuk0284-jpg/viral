# UI Navigation — 화면 이동·기간 선택 공용 규칙

새 분석 페이지를 추가할 때 **이동과 기간은 새로 만들지 않는다.** 공용 모듈을 쓴다.

## 왜 이 규칙이 생겼나 (2026-08-14 실측)

화면마다 따로 만들었더니 이동 수단이 5종류가 됐고 실제로 문제가 났다.

| 증상 | 실측 |
|---|---|
| 플로팅 '← 처음으로'와 헤더 버튼이 **겹침** | 제휴카페 화면에서 겹침 확인 |
| 라벨이 동작과 **불일치** | '‹ 카페 목록'인데 실제로는 처음 화면으로 감 |
| 같은 화살표가 **다른 뜻** | 페이저 `‹ ›`(단계) vs 월 스테퍼 `‹ ›`(달) |
| 기간 버튼이 **안 보임** | 아이콘에 마우스를 올려야 펼쳐짐(접힘폭 0 · 실제폭 977) |
| `showIntro`가 클래스를 **일부만** 정리 | `view-cx`/`view-af`가 남아 화면이 꼬임 |

## 이동 — `web/nav.js` (window.VNAV)

```js
// 화면 진입 시
VNAV.push({ id: "store:롯데 부산본점", label: "롯데 부산본점",
            open: () => openStoreScope("롯데 부산본점") });
// 헤더 맨 왼쪽에
`${window.VNAV ? VNAV.bar() : ""}`
// 화면을 다시 그린 뒤
VNAV.sync();
```

- `bar()` = `⌂ 처음` `‹` `›` 세 버튼. **어느 화면이든 같은 자리(헤더 맨 왼쪽)·같은 모양.**
- 클릭 처리는 `nav.js`가 문서 한 곳에서 받는다. **화면마다 리스너를 붙이지 말 것**
  (붙이면 재렌더 때마다 중복 등록돼 한 번 클릭에 여러 번 실행된다).
- `Alt+←` / `Alt+→` 도 같은 동작.
- `open`은 그 화면을 **다시 그리는 함수**다. 이게 있어야 뒤로/앞으로가 실제로 복원된다.
- 결과 화면에서 플로팅 `.back-float`는 **띄우지 않는다**(`nav.css`가 숨김). 헤더 내비가 대신한다.

## 기간 선택

- **항상 보이게 둔다.** hover 로 펼치는 방식 금지 — 버튼이 어디 있는지 알 수 없다.
- 화살표 기호가 이동과 겹치지 않게 한다. 월 이동은 `af-nav`처럼 **기간 바 안에** 두어
  문맥으로 구분되게 하고, 페이지 이동 화살표(`VNAV`)와 나란히 두지 않는다.
- 첫 진입은 **현재 월**. 그 달에 표본이 없으면 표본 있는 가장 최근 달로 내린다.
- 폭이 모자라면 **줄바꿈**시킨다(잘라내지 않는다). 잘린 버튼은 없는 버튼과 같다.

## 새 페이지 만들 때 체크리스트

1. 헤더 맨 왼쪽에 `VNAV.bar()`
2. 진입 함수에서 `VNAV.push({id, label, open})`
3. 재렌더 후 `VNAV.sync()`
4. 자체 뒤로가기 버튼을 **만들지 않는다**
5. 기간이 필요하면 상시 노출 + 현재 월 기본
6. 검증: 다른 화면에서 들어왔다 나갔다 하며 **뒤로/앞으로가 실제로 복원되는지**,
   버튼이 **겹치지 않는지**(getBoundingClientRect 교차 검사), 스크롤 0 인지

## 전체 점검에서 잡은 것 (2026-08-21)

### 1. view-* 클래스가 겹겹이 쌓였다 ★
화면마다 `classList.add("mode-results","view-…")` 만 하고 지우지 않아,
다이렉트웨딩 → 제휴카페 → 매장 → 리뷰로 옮기면 클래스가 이렇게 됐다:

```
mode-results view-channel view-cafe view-af view-cx view-nr
```

CSS 가 서로 간섭하고, `showIntro` 는 3개만 지워서 **'처음으로' 후에도 view-nr 이 남았다.**

→ **`window.setView("view-channel","view-cx")`** 한 곳으로 통일했다.
켤 것만 남기고 나머지는 끈다. `nav.js` 의 home 도 목록을 따로 들지 않고 `showIntro` 에 위임한다.
**새 화면을 추가하면 `app.js` 의 `VIEWS` 배열에만 넣는다** — 목록이 두 곳이면 반드시 어긋난다.

### 2. 진입 경로 없는 층은 지운다 — 부울경 사례
전국 대상이 되면서 `bu`(부울경) 층은 **지도에서 도달할 수 없는데 브레드크럼에만 남았다.**
눌러 들어가면 표본 42건짜리 요약만 있고 더 내려갈 수도 없는 막다른 길이었다.
"왜 부울경만 있고 수도권은 없나"에도 답할 수 없다.
→ `LV` 를 `["nation","region","store"]` 3단으로 줄이고 관련 분기를 전부 걷어냈다.

**규칙: 드릴 단계는 지도·목록에서 실제로 갈 수 있는 것만 둔다.**

### 3. 메인에서는 내비를 감춘다
결과 화면이 아닐 때 `⌂ ‹ ›` 가 보이면 눌러도 아무 일이 없어 고장처럼 보인다.
`body:not(.mode-results) .vnav { display:none }`.

### 4. 0건 타일은 자리만 차지한다
채널 타일 11개 중 8개가 사실상 0건이었다(결다모·웨딩북·맘스홀릭·당근 등은 수집 시도조차 안 함).
수집 계획이 없는 5개를 걷어내고, 정작 실데이터 8,348건인 **네이버 리뷰 타일을 추가**했다.
**타일은 "수집했거나 수집할 채널"만 둔다.**

## 화면은 3층이다 — 이걸 몰라서 이동이 계속 어긋났다 (2026-08-21 2차)

```
1번 메인      (클래스 없음)          애플카드 2장 + 포털
   ↓ 포털 클릭 = revealPortal()
2번 채널타일  portal-open            좌=혼수채널 / 우=제휴카페
   ↓ 타일 클릭
3번 결과화면  portal-open + mode-results + view-*
```

**`mode-results` 를 벗는다고 1번이 되지 않는다.** `portal-open` 이 남으면 2번이다.
이 구분이 없어서:

- `showIntro()` 가 `portal-open` 을 안 지워 **'처음'이 늘 2번에 멈췄고, 1번으로 갈 길이 아예 없었다.**
- 2번에는 내비를 아예 안 그렸다(`body:not(.mode-results) .vnav{display:none}` 에 걸림).
- 스택의 portal 엔트리 `open` 이 `revealPortal` 이었는데, 이미 열려 있으면 가드에 걸려 **아무것도 안 하고 반환** → 뒤로가 먹통.

**규칙 — 목적지마다 함수를 따로 둔다.**

| 가고 싶은 곳 | 함수 | 하는 일 |
|---|---|---|
| 1번 메인 | `showIntro()` | view-* + mode-results 제거 **+ `closePortal()`** |
| 2번 채널타일 | `openPortal()` | `exitResults()` 로 결과만 벗고, 안 열려 있으면 `revealPortal()` |
| 3번 결과 | `setView(...)` | 켤 view 만 남긴다 |

`closePortal()` 은 `revealPortal()` 이 한 일을 정확히 되짚는다 —
타일을 원래 부모로 되돌리고(원위치를 초기화 때 기억해 둔다), 무대·그룹·제휴모자이크를 감추고,
`portal-open` 을 벗고, 포털을 다시 보이게 하고, `applyClosed()` 로 타일을 블랙홀에 넣는다.

## 하단 페이저(⤒ ‹ ›)는 없앴다 — 내비가 두 벌이면 반드시 어긋난다

같은 화면 상단에 VNAV 가 있는데 하단에 페이저가 또 있었다. 그런데 **둘은 서로 다른 것을 셌다**:

- 상단 `‹` = **지나온 화면**(스택)
- 하단 `‹` = **드릴 단계**(전사↔지역↔매장)

생김새가 같은 두 버튼이 화면마다 다른 곳으로 갔다. 하단을 걷어내고 이동은 VNAV 하나로만 한다.
드릴은 지도·표를 직접 누르는 것으로 충분하다.

## 새 화면을 만들 때 반드시 확인 — 내비를 그렸는가

`VNAV.push()` 만 하고 **`VNAV.bar()` 를 안 그리면 들어가서 나올 수 없는 막다른 화면**이 된다.
채널 단일 화면(블로그·유튜브 등)이 실제로 그랬다 — 스택엔 있는데 버튼이 없었다.

**두 가지가 짝이다: `push()` + `bar()`.** 하나만 하면 반쪽이다.
