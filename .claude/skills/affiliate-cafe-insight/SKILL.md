# Affiliate Cafe Insight

제휴카페는 **지역 생활 커뮤니티**다. 혼수 후기 건수로 재면 전부 0에 가깝게 나오지만,
다른 축으로 보면 경쟁·수요·활동성과 신호가 나온다. 이 스킬은 그 축으로 정리한다.

## Step 0. 대상 선정

`artifacts/affiliate-cafes.json`(84곳, clubId 포함)에서 고른다. 우선순위:

1. **부울경 14곳**(우리 권역) — 회원수순: 거사모 46.9만 / 울산 부동산 재테크 35.4만 /
   창원부동산이야기 21.4만 / 러브양산맘 18.8만 / 살통영 15.0만 / 진주아지매 13.3만 …
2. **백화점 소재 도시** — 창원·진주·김해·마산·부산·울산.
   (거제·통영·양산에는 백화점이 없다. 이 지역은 전자랜드·하이마트 경쟁 지역으로 따로 본다.)
3. 전국 대형 — 국민임대아파트 92만, 내집장만 아카데미 56.6만(둘 다 전국구·이사 수요 밀집)

한 번에 다 돌리지 않는다. **3~5곳씩 돌려 수확을 보고** 확장 여부를 정한다.

## Step 1. 수집

```
VIRAL_CLUBID=<clubId> VIRAL_CAFE_URL=<url> python scripts/naver_cafe_scraper.py \
  scrape --query "<아래 쿼리셋>" --pages 3 --max-articles 60 --no-read-body --headless
```

권장 쿼리셋(‘구매’ 금지 — 중고장터가 쏟아진다):
```
냉장고||세탁기||건조기||에어컨||TV||김치냉장고||가전 추천||가전 어디서||가전 견적||
전자랜드||하이마트||삼성스토어||디지털프라자||베스트샵||엘지 서비스
```

정확도가 필요하면 `--read-body`(느림, 로그인 세션 필요). 로그인은 사용자가 직접.

## Step 2. 8축 분류

처음엔 5축이었으나 실측하며 3축이 늘었다(구독·렌탈 / 사후서비스 / 온라인).
`scripts/affiliate_insight.py`가 정의하며, **판별 순서가 곧 우선순위**다.

| 순 | 축 | 판별 신호 | 왜 이 순서인가 |
|---|---|---|---|
| 1 | ② 경쟁유통 노출 | 업체명 + 행사·세일·초대 | 홍보글은 다른 축으로 새면 안 된다 |
| 2 | ⑤ 중고 거래 | 삽니다·팝니다·업소용 | 표본을 가장 많이 오염시킨다 |
| 3 | ⑦ 사후 서비스 | 청소·세척·수리·설치·철거 | **‘문의’만 보면 세탁기 분해청소가 구매문의로 잡힌다** |
| 4 | ⑥ 구독·렌탈 | 구독·렌탈·리스 | AI구독클럽 대응 지점 |
| 5 | ⑧ 온라인 구매 | 쿠팡·11번가·온라인 | 오프라인 반격 논리 재료 |
| 6 | ③ 구매·추천 상담 | 어디서·잘해주는·견적·추천 | 위를 거른 뒤라야 진짜 구매 의도만 남는다 |
| 7 | ① 교체·이사 | 고장·수명·이사·입주 | 혼수와 다른 생활 수요 |
| 8 | 생활잡담(제외) | 정리·요리·반찬·냄새 | **‘냉장고’만 보면 냉장고 정리글이 수요로 잡힌다** |

④ 제휴활동 = ② 중 삼성 계열이 올린 글(별도 플래그).

브랜드·품목 분류는 `scripts/brand_lexicon.py`와 `scripts/build_web_data.py`의
`ITEMS`/`RET_RE`/`dept_store_of`를 재사용한다. 여기서 새로 정의하지 않는다.

## Step 3. 인사이트 도출

기계적 집계로 끝내지 말고 **판매로 이어지는 해석**까지 간다.

- ②에서 **우리 노출이 경쟁사보다 적은 지역** → 제휴 원고 우선 배치 후보
- ③의 문의 글에 **경쟁 유통이 추천되고 있으면** → 그 카페는 방어가 필요한 곳
- ①의 교체 수요가 큰 품목 → 해당 지역 매장의 **단품·긴급 대응 재고**
- ⑤ 중고 거래가 많은 지역 → 보급형·전시품·구독 제안이 통할 세그먼트
- ④에서 반응 좋은 문구 → 다른 카페로 확산

## Step 4. 정직성 규칙 (필수)

- **표본 수를 먼저 쓴다.** 적으면 적다고 쓴다. "N건 기준"을 제목 옆에 붙인다.
- 표본 10건 미만에 **비율(%)을 쓰지 않는다.** 건수로만 쓴다.
- 제휴카페 수치를 **다이렉트결혼준비와 합산하지 않는다.** 별도 표로 둔다.
- 수집 안 된 카페는 "미수집"으로 적는다. 추정치로 채우지 않는다.
- 백화점 없는 지역(거제·통영·양산 등)은 **매장 비교 대상이 아님을 명시**한다.


## Step 5. 웹 화면으로 내보내기 (2026-08-12 추가)

리포트(.md)로 끝내지 않는다. 대시보드에서 **제휴카페 타일을 누르면 바로 보이게** 한다.

```
python scripts/build_affiliate_web.py     # artifacts/affiliate/*.json → web/assets/affiliate-insight.js
```

- 미리 합산하지 말고 **글 1건 = 1행**으로 내보낸다.
  월 단위·전체 기간을 같은 코드로 처리해야 "어느 한쪽만 기간 연동되는" 사고가 안 난다.
- 행 구조: `[ym, 축코드, 유통비트, 품목비트, 우리글여부, 제목, articleId]`
  URL은 `clubId + articleId`로 화면에서 조립한다(용량 절감).
- 분류 규칙은 `affiliate_insight.py`에서 임포트한다. **여기서 다시 정의하지 않는다.**

화면(`web/affiliate-view.js`)의 원칙:

| 원칙 | 이유 |
|---|---|
| 좌=가전 전반 / 우=당사 **2단 고정** | 섞으면 "가전 이야기는 많은데 우리만 없다"가 묻힌다 |
| 헤더에 `가전 글 N vs 당사 M` 대비 | 이 화면의 결론을 먼저 때린다 |
| 유통 표에서 **당사를 맨 위 고정** | 건수순이면 우리가 꼴찌라 표 아래로 밀려 안 보인다 |
| 첫 진입 = **현재 월** | 지난 달 상황이 지금 상황처럼 보이면 안 된다 |
| 글씨 본문 19px | 다이렉트웨딩 분석 페이지와 같은 크기 |

### 판정은 세 갈래로 나눈다 (필수)

뭉뚱그리면 "당사가 없다"가 과장된다. **실제로 겪은 오류다** —
올댓창원 2026-08은 수집 5건이 전부 "새벽에 에어컨 끄고 잤네요" 같은 일상 대화였는데
화면이 "이 카페에 당사가 없습니다"(적색)로 표시했다.

| 상황 | 표시 |
|---|---|
| 수집 0건 | "이 달은 수집된 글이 없습니다" |
| 가전 이야기 0건(잡담만) | "이 달은 가전 이야기가 없습니다" |
| 가전은 있는데 당사 0 | "이 카페에 당사가 없습니다" (적색) |
