# Viral Monitor — 혼수 가전 바이럴 모니터링 하네스

온라인 혼수가전 **구매후기**를 조사·분석하여, **전국 백화점에 입점한 삼성스토어 vs LG전자 매장**의
바이럴(구매후기) 현황을 매장·지역 단위로 비교하고, **삼성스토어가 LG보다 혼수 판매를 늘릴 인사이트**를 찾는다.

## 목적 (2026-06 개정 — 백화점 입점 매장 중심으로 재정의)

1. **대상 = 전국 백화점 입점 삼성스토어 vs LG전자 매장**의 혼수가전 구매후기 비교.
   - 비교 단위: ①전국 ②지역별 백화점 ③백화점 내 삼성 vs LG. 다양한 시각으로 드릴다운.
2. **모니터링 후기 = 혼수가전 구매후기**. "웨딩가전·신혼가전·혼수가전·가전 졸업" 등 표현이 다양하나, 결국 **결혼하며 구매하는 가전 후기**를 가리킨다.
3. **백화점 입점 매장 외 데이터는 분석에 사용하지 않는다(보관만).** 삼성스토어 단독매장·대리점·하이마트·온라인몰 등은 census에 보관하되 본 분석/대시보드 집계에서는 제외.
4. 목표 = LG 대비 우위·열세 진단 → **삼성스토어 혼수 판매 증대 인사이트** 도출.

## 백화점 매장 명칭 규칙 (집계 핵심)

- 후기에서 매장은 **백화점명 + 브랜드** 조합으로 불린다.
  - 백화점: 롯데·신세계·현대·갤러리아·AK 등 (약칭 롯/신세/현/갤 포함). 예) 롯데백화점 잠실점 → **롯데잠실 / 롯잠실 / 롯본점(본점)**.
  - 브랜드: 삼성·삼·삼성스토어 / LG·엘지·엘·하이프라자·베스트샵.
  - 예) "롯데잠실 삼성", "롯잠실 엘지", "신세계 강남 LG", "현대 판교 삼".
- 매장 키 = **백화점지점 + 브랜드(삼성/LG)**. 같은 백화점 지점에서 삼성 후기 vs LG 후기를 비교한다.
- 백화점 단서가 없는 후기는 "백화점 미상"으로 분류(분석 제외, 보관).

## 소스 선택

- 모니터링할 사이트는 `data/sources.md` 카탈로그에서 **복수 선택**한다 (카페·블로그·커뮤니티·SNS).
- 세션 시작 시 사용자에게 소스를 고르게 하고, 선택한 소스만 수집·집계한다.
- 결과는 **소스별로 분리**해 보여준다 (사이트마다 표본·성향이 달라 합산 해석 주의).

## 공통 규칙

- **분석 범위 = 2단 구조(2026-06 재조정).** ①**전국·지역 = 전체 후기 대상**으로 센싱(백화점 포함 모든 유통). ②**지역에서 매장을 특정할 때만 백화점 입점(롯데·신세계·현대·갤러리아·AK) 삼성스토어 vs LG전자**로 비교 — 그래야 삼성 vs LG 구도가 성립. census 전량은 보관.
- 매장 키 = **백화점지점 × 브랜드(삼성/LG)**. 명칭 약칭(롯잠실·롯본점·신세 강남 등)도 정규화해 같은 지점으로 묶는다.
- 모든 산출물은 `artifacts/` 아래에 `YYYYMMDD-` 접두사로 저장. 전수 census = `artifacts/cafe-census.json`(백화점 외 포함 보관), 분석용 = 백화점 필터 적용분.
- 웹 검색 결과는 **출처 URL을 반드시 함께 기록**한다 (검증 가능성 확보).
- 백화점 단서가 불명확한 후기는 "백화점 미상"으로 분류(분석 제외, 버리지 않고 보관).
- 집계는 추정임을 명시한다. 표본은 전수가 아니므로 "표본 기준 추정치"로 표기. 제목기반 추정과 본문확정을 구분 표기.


## 작업 후 되돌려 적기 (필수)

이 하네스가 계속 발전하려면 **한 번 배운 것이 파일에 남아야** 한다.
작업이 끝나면 아래를 확인하고, 어긋난 것이 있으면 그 자리에서 고친다.

| 확인 | 어디에 |
|---|---|
| 새로 만든 스크립트·산출 경로 | 해당 스킬의 실행 절차 |
| 함정·실패담(왜 그렇게 하면 안 되는지) | 해당 에이전트의 "배운 것" 절 |
| 분류 기준·축이 바뀌었나 | 스킬 + 에이전트 + 이 파일 + `data/agent-roster.md` **네 곳 모두** |
| 화면 원칙이 생겼나 | 스킬의 화면 절 |
| 사용자가 정정해 준 사실 | 메모리(`memory/`)에도 남긴다 |

**실제로 겪은 문제(2026-08-12):** 제휴카페 작업을 마쳤는데 스킬·에이전트 파일에
`build_affiliate_web.py`도 웹 화면도 월 단위도 적혀 있지 않았다. 축은 8개로 늘렸는데
문서는 5축 그대로였다. 이 상태로 다음 사람이 스킬만 읽으면 **리포트만 만들고
화면은 옛 수치를 계속 보여준다.** 코드와 문서가 갈라지면 하네스는 껍데기가 된다.

> 판단 기준: **"맥락을 모르는 사람이 이 파일만 읽고 같은 결과를 낼 수 있는가."**
