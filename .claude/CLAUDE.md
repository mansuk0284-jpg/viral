# Viral to Insight — 가전 바이럴 통합 모니터링 하네스

**각종 온라인 채널에서 가전 바이럴(고객이 남긴 글·영상·리뷰)을 수집·분석해
전국 → 지역 → 매장 단위로 보여주는 대시보드.**

본류는 **혼수(웨딩) 가전 구매후기**지만 거기에 멈추지 않는다 — 웨딩카페의
구매후기, 블로그·유튜브·인스타·오늘의집 같은 넓은 채널의 가전 이야기,
제휴카페의 생활 수요, 네이버 플레이스의 매장 방문자 평가까지 **여러 채널의
바이럴을 한곳에 모아** 같은 매장을 여러 각도에서 본다.

## 1. 화면 지도 — 프로그램이 보여주는 것

```
메인(index.html)
 ├ 좌: 히어로 영상 + 접속자 카운터
 ├ 우: 채널별 바이럴 카드(타일 요약) · 우리 매장 바이럴 카드(매장 선택)
 ├ 채널 축 — 채널 하나 = 화면 하나
 │   다이렉트웨딩(전국지도→지역→매장 3단 드릴) · 제이웨딩 · 네이버 블로그(3단 드릴)
 │   유튜브 · 인스타그램 · 오늘의집 · 제휴카페(2번 페이지)
 └ 매장 축 — 매장 허브(store-scope): 매장 하나를 놓고 채널마다 카드 하나
     카드 클릭 → 그 채널의 매장 상세(다결·블로그·네이버리뷰는 직행 API)
```

**채널 축과 매장 축은 같은 데이터다**(2026-08-23 사용자 정리) — 바라보는
시각만 다르다. 그래서 **새 채널을 붙일 때는 반드시 둘 다 만든다**:

| 만들 것 | 어디 |
|---|---|
| 채널 데이터(두 축) | `scripts/build_{채널}_web.py` — `total/s/l/months/items` + `stores{…}` + `monStores`(ym→매장→수치) |
| 히어로 타일 | `web/index.html` 의 `#sourceMosaic` + `data-go` 분기 |
| 채널 화면 | `web/{채널}-view.js` — `window.open{채널}()` |
| 매장 카드 | `web/store-scope.js` 의 `CHANNELS` 배열 + `{채널}Card()` + `chCounts()` 한 줄 |

**채널 줄에 두는 것**(2026-08-24): 혼수 기반 바이럴 채널만 — 웨딩카페
본류(다결·제이웨딩·블로그·맘카페) + 넓은 채널(유튜브·오늘의집·인스타, 그 안에서
혼수가전만 골라 본다). **네이버 리뷰는 매장 평가라 채널 줄에 두지 않는다** —
매장별 현황에만. 히어로의 '누적 N건 센싱'은 채널 줄 타일의 합이다.

**접속자 카운터**: `web/visit-counter.js`, 메인 좌측 영상 바로 아래.
Abacus(keyless, ns `mansuk0284viral`/`visits`), 세션당 1회·45초 폴링,
배지는 **항상 즉시 표시**(차단 환경 폴백 "—"/localStorage). 사내 참고용
눈금이지 감사 지표가 아니다.

## 2. 세 가지 잣대 — 같은 매장을 다르게 본다 (합산 금지)

| ③ 매장 평가 | 실제 **방문 고객의 리뷰·예약** | 네이버 플레이스(131매장) | naver-review-analyst |

## 4. 데이터 파이프라인 — 수집 → 병합 → 빌드 → 화면

```
채널 수집기(scripts/collect_*·naver_cafe_scraper board) → artifacts/*.json
  ①-b 다결 다리: merge_board_into_census.py  (board 누적본 → census)
→ scripts/build_*_web.py (7종) → web/assets/*.js (CAFE_DATA·NBLOG·JWEDDING·…)
→ 화면 JS 가 기간으로 잘라 그린다 (VPER 기간 UI + VFACT/monStores 집계)
```

- **다결은 두 갈래다**: `board --cumulative`는 정본 누적본
  (`cumulative-cafe-raw.json`)에만 저장하고 **빌드는 census만 읽는다**.
  `merge_board_into_census.py`가 그 다리 — board 증분 후 반드시 실행(배치
  ①-b). 이 다리가 없으면 board가 걷어온 최신 글이 화면에 영원히 안 나온다
  (실측: 8월 하순 +201·9월 586건이 잠겨 있었다).
- **기간 칩은 데이터에서 자동 파생** — 각 채널 자산의 `months`를 빌드가
  수집분에서 만든다. 그 달 데이터가 자산에 실리면 칩은 자동으로 생긴다.
- **기간 연동의 화면 패턴**: 수치를 넣기 전에 `hasF() ? A() : CD`(또는
  `perData()`)를 쓰는지 확인한다. 빌드 고정값(`CD.*`)을 직접 읽으면 기간을
  바꿔도 안 변한다(매니저 실명 카드 실사고 — 데이터는 `VFACT.agg()`가 기간별로
  이미 만들고 있었고 화면만 안 쓰고 있었다). 의심되면 콘솔에서
  `window.VFACT.agg(start,end)`를 직접 불러 **데이터 문제인지 화면 문제인지**부터
  가른다. 점검: `grep -n "CD\.\w\+" web/cafe-analysis.js`.
- **매장 이름은 `build_web_data.dept_store_of()`를 재사용한다** — 채널마다 따로
  뽑으면 같은 매장을 다른 이름으로 불러 화면이 어긋난다. 이 함수를 고치면
  반드시 전/후 전량 diff → 방향 눈검수 → 재빌드 공정을 거친다(§5.3 store-matcher).
- **수집 범위 = 2026년**(2026-08-24 사용자 지시): 새로 수집하는 것은 2026년치만,
  과거분(2021~2025)은 보관·표시 유지. 기간을 못 고르는 채널(유튜브·인스타)은
  전량 수집하고 화면 기간 탭으로 2026을 본다. "최대한"은 **쿼리를 넓히는 것** —
  월별 윈도 × 쿼리 union이라 쿼리 수가 곧 수확량(34개:
  가전,후기,삼성,엘지,LG,냉장고,세탁기,건조기,에어컨,TV,티비,청소기,디오스,비스포크,
  스타일러,김치냉장고,인덕션,식기세척기,정수기,오브제,트롬,그랑데,무풍,에어드레서,
  워시타워,광파오븐,혼수,신혼,웨딩,가전졸업,견적,계약,백화점,하이마트).
- **재훑기는 `.done`을 지워서 연다**: census는 완료월(`2026-09` 형식),
  블로그는 `쿼리|YYYYMMDD`(윈도 **시작일** — `|2026-08`은 0건 매치 실사고).
  articleId/URL로 중복을 거르므로 다시 훑어도 기존 글이 늘지 않는다.
- **매장 후기 원문은 census 동적 샘플**: 빌드가 `CD.storeSamples`(제목·작성일·
  조회수)를 싣고 화면이 선택 기간으로 잘라 우호 3·주의 2건. 월별 상한은
  **브랜드별**(삼성/LG 각 우호 2·주의 1) — 조회수 상위만 남기면 회수율 높은
  삼성이 달을 독차지해 LG 원문이 사라진다. 기간 안 샘플이 없으면 최신 글 +
  "가장 최근 후기" 명시.
- **보조 데이터 — 혼인 통계**(`build_marriage_web.py` → `marriage.js`):
  공식치 = 통계청 인구동향 월별 발표(출처 URL은 스크립트 머리 주석) + 연간
  확정. 미발표월 추정 = 2021~25는 잔여 균등 배분(연간 검산 assert), 2026은
  전년 동월 × 발표월 평균 증감률. 라벨이 구성 따라 "통계청 인구동향/· 일부
  추정/추정"으로 바뀐다. 지역은 전국 공식 × 시도 비중(인구×조혼인율 보정,
  미확보 시도는 1.0) — 라벨 항상 "추정". **새 월 발표가 나오면 OFFICIAL에 한 줄
  추가하고 재빌드**. 회수율(혼인 1,000건당 후기)의 기준선은 같은 지역의 전
  기간과 비교한다(전국과 섞지 않음).

- **임무**: 혼수 브이로그·가전 리뷰 영상에서 가전 바이럴 신호를 수집한다.

  20개(성능·비교·신모델 — 혼수 낱말 면제, 가전 낱말 필수). id 중복 제거,

  채널명 ∨ 제목 어휘)을 분류하고 공식 채널은 spec에서 제외.

  전"은 월 집계 제외, 카드에 "게시월 추정" 배지). 첫 화면 = 최근 3개월
  (`VPER.setInit`). 공식/유튜버/전문 순위 카드는 서로 중복 없음, 기간 안에
  없으면 전체 기간 상위 + 정직 문구 폴백.
- **배운 것**: 기간을 못 고르는 채널은 **검색어 수가 곧 표본 크기**다(8→26개로
  54→97편). 검색어엔 가전 낱말·제품명 필수 — "혼수 준비" 같은 넓은 말만 쓰면
  예식장·드레스가 끌려온다.

  차단으로 난다. 판별법 = `insta_login.py`를 띄우면 5초 안에 "로그인 확인됨 ·
  태그 페이지 읽힙니다"까지 자가 진단 — 통과하면 재로그인 없이 재수집만.

### 5.2 channel-access-engineer — 채널 접속(로그인)

- **임무**: 채널별 로그인·접속 문제 해결. 사용자 직접 로그인 세션을 수집
  프로필에 저장·점검해 공개검색의 빈약한 표본을 넘어서게 한다.
- **철칙: 비밀번호는 코드가 절대 입력하지 않는다** — 로그인은 항상 사용자
  직접(`insta_login.py` 등). 채널 수집가는 "로그인 세션 우선, 없으면 공개검색
  폴백".
- **수집 프로필 = `.browser-profile2`** (전 수집기 공유 — 동시 실행 금지,
  배치는 순차). 원래 `.browser-profile`이었는데 다른 로그온 세션의 **유령
  크롬**이 경로를 쥐어 즉사("기존 브라우저 세션에서 여는 중입니다")했다 —
  파일 잠금 0이어도 크롬 인스턴스 탐지는 경로 문자열 기준이라 걸린다. 해법 =
  프로필 복제(robocopy·캐시 제외) + 스크립트 경로 치환. 로그인 쿠키는
  Default+Local State에 있어 사본에도 유지된다.
- **이 폴더는 개인 계정 쿠키다 — 외부 전달 절대 금지**(인수인계 시 제외).

## 6. 전 에이전트 공통 원칙

### 6.1 숫자의 원칙 — 지어내지 않는다

- 없는 데이터는 "없음/추정"으로 정직하게. 집계는 "표본 기준 추정치" 명시.
- **표본 10건 미만이면 퍼센트를 적지 않는다**(9건으로 "100%"라 쓰면 한 건에
  89%가 된다) — 건수로만 말한다.
- **실행 불가능한 목표는 목표로 걸지 않는다** — 누적을 못 뒤집을 땐 "새로
  쌓이는 속도"로 목표를 바꾼다(격차 7,208건에 "월 601건씩"은 포기 사유).
- **매장 우위/열세는 있는 그대로의 건수 비교**(2026-08-25 사용자 정정): 1:0도
  있는 쪽이 우위. 분모는 "전체 백화점 71개점". 회수율 편향(삼성 7.7% vs LG
  3.8%)은 사실로 밝혀 둔다. **이 판단은 뒤집힐 수 있다** — 같은 사용자가 전에
  반대로 판단했었다. 다시 바뀌면 그때 지시대로.
- **사실 고지와 해석 지시는 다르다**: 사실은 반드시 밝히되 "~하지 마세요/~해야
  합니다" 류 지시문은 꼭 필요한지 먼저 따진다 — 읽는 법은 회사 사람들이
  판단한다.
- 전국/지역/매장의 조회수 합계는 **매장 특정 후기 기준**임을 라벨에 밝힌다.

### 6.2 문장의 원칙 — 쉽고 정확하게, 말하듯

- **후기의 주체는 고객이다**: 후기는 고객이 쓴다 — 매니저가 할 수 있는 건
  **요청·독려**뿐. "후기를 늘리세요"(×) → "구매 고객에게 후기 작성을
  요청하세요"(○). "좋은 후기 만들기"(×) → "좋은 후기가 나오려면"(○).
- **인사이트 판별법**: 승패가 뒤바뀌어도 같은 문장이 나오면 인사이트가 아니다.
  지표의 사전적 정의 대신 "그래서 무엇을"이 든 문장(매장 실명·품목·다음 행동).
  방법론 고지는 필요하지만 그것'만' 남으면 안 된다.
- **±0에는 판정어를 붙이지 않는다**: 비교 수치 문장은 반드시 **삼지선다**
  (>0/<0/=0) — 0이면 "같은 수준". 추이를 볼 수 없는 설정이면 돌려 말하지 말고
  "월별 추이를 확인할 수 없습니다". 연장: 열세 1곳뿐이면 "격차의 100%" 대신
  "유일한 열세 매장", 반올림이 안 변하면 전환 효과 문장 금지(projected >
  current일 때만), 표본 1곳이면 "100~100% 편차" 같은 모순 금지.
- **비교형 템플릿은 경계를 확인한다**: 단일 월·표본 1개·동률에서 무슨 문장이
  나오는지 반드시 본다("8월 최다, 8월 최저" 실사고) — 경계에선 비교 대신 안내로.
- **분석글은 최소 2줄** — 축약이 해석을 막으면 실패. 카드 요점 칩도 수치
  조각("우위 52%")이 아니라 내용이 짐작되는 문구("삼성 비중 52% 접전").
- **자연어로 쓴다**(2026-09-26~30 라운드): "발생분/갈라 셌습니다/직전 같은 길이
  구간/성과 요인" 같은 경직 표현 대신 말로 푼다. 이중 부정 금지("-5p
  낮습니다" → "5p 낮습니다", 칩의 부호는 유지). 압축 명사구보다 풀어낸 문장
  ("우위에 가려진 상대 열세" → "이기고는 있어도 이웃 매장들만큼은 아니라는 뜻").
- **섹션 제목은 문어체 명사구** — 질문형("~인가")·구어체("쏠림") 금지. 은유
  (새다·터지다·뿌리다) 대신 우위/열세/이탈/격차. **용어 치환표**(화면 문자열만,
  주석은 무관):

| 쓰지 말 것 | 쓸 것 |
|---|---|
| 갈라 세다/보다/읽다 | 별도 집계 / 구분 집계 |
| (글을) 마케팅 물량 | 체험단·협찬 **게시물** |
| 글을 뿌리다 | 협찬 마케팅을 **집행**하다 |
| 검색 화면을 쥐다 | 검색 상위 노출을 **점유**하다 |
| 글이 덮다 | 비중이 높아 노출이 가려지다 |
| 옮길 교본 | 적용할 **모범 사례** |
| 바이럴의 관문 | 바이럴의 **핵심 거점** |
| 글이 몰리다 | 게시물이 **집중**되다 |
| 읽힘/hit | **조회수**(글·영상 공통 확정 용어) |
| LG가 조용한 구간 | 경쟁사 **노출이 적은** 구간 |

  검사법: `grep -n "물량\|뿌리\|쥐고\|덮고\|교본\|몰리\|읽힘\|읽히" web/*.js | grep '\`'`
- **조사는 받침으로 고른다**: 은/는·이/가 = `josa()`/`hasJong`, 숫자 뒤
  '(으)로' = `numRo()`(끝자리 소리 — 1·7·8은 '로'). 나열 끝이 매장 이름이면
  하드코딩 조사 금지("센텀시티은" 실사고). **주의: 조사 정규식 검수는 관형형
  어미 '-는'(있는/없는)을 조사로 오인한다** — 검출은 육안으로 가른다.
- **모든 분석 페이지는 "실행 제안 — 역할별"로 끝난다**: `.role-plan`
  (본사/영업팀/매장 세 줄) — 그 페이지의 실데이터에서 도출한, **수단이 명시된**
  문장(교육·판촉·후기 요청 캠페인·콘텐츠 기획). 일반론 금지, 분기마다 문장이
  달라야 한다. 누락 점검: `grep -l "role-plan" web/*-view.js web/store-scope.js`.

### 6.3 색·표기 원칙

- **긍정 = 파랑 · 부정 = 빨강** — 카드 앞면(칩·미니 수치 `miniNeg`/`{t,neg}`)과
  상세 본문(`b.warn`) 모두. `.warn` 전역 오버라이드는 `cafe-analysis.css` 맨

  양 끝, 수치는 아래 양 끝(264px 칼럼에서 일곱 자리 둘을 한 줄에 못 놓는다 —
  두 줄 세로 쌓기).
- **숫자를 나란히 붙이지 않는다**: "82%977"이 되지 않게 실제 공백 문자 +
  구분자·단위(` · 977건`) — CSS margin은 복사·스크린리더에 전달되지 않는다.
- 표기: 후기 건수·조회수 모두 "브랜드 N건/회(퍼센트%)". 기간 라벨은 하이픈
  (`2026-03-01 ~ 2026-05-31`).

## 7. 화면(UI) 원칙

### 구조
- **단위마다 묻는 것이 다르다**(전국/도시/매장):

| 단위 | 묻는 것 | 화면에 두는 것 |
|---|---|---|
| 전국 | 구조가 어떤가 | 규모·지도 · 우위/열세 구조 · 품목 지형 · 실명 · 몇 개점 우위 |
| 도시 | 어디쯤·안에서 얼마나 갈리나 | 순위·전국 대비 · **매장 목록(주인공)** · 도시 안 격차 |
| 매장 | 무엇을 어떻게 할까 | 품목·혜택·추이 · 계약 규모 · 실명 · 현장 액션 · 후기 원문 |

  매장급 디테일을 도시에 두지 않는다(진단이 529px을 먹어 서울 20곳이 행
  6px로 찌부러진 실측). 도시 진단 max-height 54%·목록 min 170px·12곳 초과면
  2열. 도시 액션은 한 수만 짚고 "매장을 눌러 확인"으로 넘긴다.
- **좌측 = 요약 / 우측 = 진단(총론 → 각론 ①②③ → 실행 제안)**. 좌측 칼럼은
  제목 있는 섹션 박스(`.nsc-sec`/`.nsc-st`) 문법 통일, 폭 `clamp(230px,20vw,288px)`
  (전국·지역 공통 — 전환 시 경계가 안 튀게). 지역도 전국 양식 + 지역 디테일
  (최강/공략 픽, 전국 안 위치). 우위·열세 지역 요약은 좌측이 아니라 **지도
  아래 범례 곁**(지도의 설명이므로).
- **좌측 요약은 압축 밀도**: 보조 활자 14px/1.42 단계(선택자 목록은
  analysis-ui.css), 트렌드 불릿 3개 상한. **우측 카드 여백은 기존 computed
  값을 재기 전에 줄이지 않는다**(실측 없이 덮었다가 페이지가 오히려 늘어난
  실사고).
- **매장 허브 = 채널 허브**: 좌측 큰 숫자는 노출 채널 전부의 합(`chCounts()` —
  새 채널은 여기도 한 줄), 주요 채널 상위 3 칩, 카드 클릭 → 채널 매장 화면
  (`display:contents` 래퍼). 브랜드 비중 막대는 삼성/LG가 갈리는 채널만
  합산(리뷰·인스타 제외 — 각주 명기). 오늘의집 카드는 "수집 대기"가 아니라
  **매장 축 없음**. 좌측 요약 진단 = `chSummary()`(우위/열세 실명·전월비
  흐름·격차 최대 — 리뷰 격차도 worst 후보에 넣어야 모순이 없다).
- **전월비 추세는 페이스로 판정**(`moTrend()`): 당월은 진행 중이라 절대 건수
  비교는 항상 하락으로 오독 — 경과일 환산 월말 페이스 vs 전월, ±15% 문턱,
  둘 다 3건 미만이면 보합, 근거는 title 툴팁. 리뷰는 전월이 커버 밖이면
  화살표를 만들지 않는다.

  실결함과 가른 뒤에만 고친다.
- 소표본·경계(단일 월·0건·동률·짝 없음)는 별도 분기로 직접 눌러 본다.
